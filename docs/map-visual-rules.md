# Map visual rules (2D/3D readability contract)

Документ фиксирует единые правила отображения сетевых элементов (узлы и кабели) на 2D-карте и 3D-глобусе. Цель — гарантировать, что легенда, песочница, карточка предложения и глобальная карта показывают одну и ту же семантику.

## 1. Источники истины

- Цвета кабелей: `CABLE_COLORS` в `src/lib/three/factories.ts`.
- Цвета и размер узлов: `NODE_VISUALS` в `src/lib/three/factories.ts`.
- Иконки узлов на 2D-картах: `src/lib/leaflet/proposalNodeIcons.ts` (`buildProposalNodeDivIcon`, `getProposalNodeLegendSvg`).
- Канонический рендер кабелей (эталон): `src/app/networks/[id]/page.tsx` (effect MAP_2D и THREE-эффект).
- **Единый реестр легенды**: `src/lib/networkLegend/registry.ts` (`NETWORK_LEGEND_GROUPS`, `getLegendItem`, `SATELLITE_BACKHAUL_KEY`).
- **Helpers рендеринга легенды**: `src/lib/networkLegend/render.tsx` (`NetworkLegendItemRow`, `NetworkLegendNodeIcon`, `NetworkLegendLineSample`, `getLegendLineStyle`).

Все три экрана (`/sandbox` sidebar, `/networks/[id]` ProposalLegend, `/global-network` GlobeLegendBody) обязаны рендерить легенду только через реестр и helpers. Любые отклонения в `MapView.tsx` или `sandbox/page.tsx` от этих источников считаются багом и должны быть подтянуты к канону.

## 2. Канонический контракт линий (2D)

| Слой           | Параметры                                                |
| -------------- | -------------------------------------------------------- |
| Shadow pass    | `color: '#071120'`, `weight: 6`, `opacity: 0.24`         |
| Main pass      | цвет из `CABLE_COLORS` или `#8ab4f8` для satellite       |
| Main weight    | `3`                                                      |
| Main opacity   | `0.92`                                                   |
| Underground    | `dashArray` top: `'8,6'`, shadow: `'9,7'`                |
| Satellite link | `dashArray` top: `'2,6'`, shadow: `'3,7'`, цвет `#8ab4f8` |

Условие satellite определяется по `metadata.linkKind === 'satellite'` элемента кабеля.

## 3. Канонический контракт линий (3D)

- Глобус (предложение): `LineBasicMaterial`/`LineDashedMaterial` с цветом из `CABLE_COLORS`, opacity 0.85–0.9.
- Глобус (глобальная сеть): `getCableKit()` в `src/lib/three/syncGlobeNetworkElements.ts`.
- Подземные — пунктир (`LineDashedMaterial`, `dashSize: 0.04`, `gapSize: 0.03`).
- Satellite link — пунктир `dashSize: 0.02`, `gapSize: 0.05`, цвет `#8ab4f8`.

## 3.1 Контракт распознаваемости 3D-узлов (приоритет: текущий стиль проекта)

Цель: пользователь должен различать тип узла по силуэту за 1-2 секунды без опоры только на цвет.

- `MULTIPLEXER` — цилиндрический узел с акцентом на кольцевые элементы вокруг корпуса.
- `DEMULTIPLEXER` — отдельный силуэт, отличимый от `MULTIPLEXER` геометрией/ориентацией выходных каналов.
- `BASE_STATION` — выраженная вертикальная мачта + секторные панели/антенные блоки.
- `REGENERATOR` — стойка/блок усиления с характерными боковыми портами и радиаторной зоной.
- `SMS_GATEWAY` — прямоугольный шлюзовой корпус с антеннами и front-панелью портов/индикаторов.
- `VSAT_TERMINAL` — тарелка с опорой и feed-arm/LNB, читаемый профиль антенны.
- `SWITCH` — низкий rack-like корпус с выраженной портовой гранью.

Ограничения:

- Не уходим в плоский (flat) 2D-стиль; сохраняем текущий material-подход (`MeshPhong/Metal/LED`).
- Не меняем бизнес-логику и контракты данных, только factory-геометрию и связанные визуальные соответствия.
- Любые изменения `NODE_VISUALS.size` проверяются на посадку узла по радиусу сферы (без клиппинга и "зависания").

## 4. Иконки узлов (2D)

- Силуэт узла обязан читаться на любой OSM-подложке.
- В `svgWrap` используется двухпроходный stroke: тёмная нейтральная обводка снизу (`rgba(8,15,28,0.92)`, `stroke-width: 3.4`), затем цветной верхний штрих (`stroke-width: 1.9`).
- Внутренний металлический градиент сохранён для 3D-вида.
- Drop-shadow на обёртке `divIcon`: `drop-shadow(0 2px 3px rgba(8,15,28,0.55)) drop-shadow(0 0 1.4px rgba(8,15,28,0.85))`. Цветной bloom не использовать.
- Размер: 30 px для `SERVER`, 28 px для остальных.

## 5. Тултипы

- `className: 'map-tooltip'` стилизуется глобально в `src/app/globals.css`.
- Контракт фона/контраста: тёмный фон `rgba(10,20,45,0.94)`, текст `#eaf2ff`, рамка `rgba(120,160,255,0.35)`.

## 6. Критерии приемки читаемости

Релиз считается «читаемым», если выполняются все пункты:

1. На любом фрагменте OSM (city/forest/coast/desert) тип кабеля определяется без подсматривания в легенду за 1–2 секунды.
2. Узел любого типа сохраняет распознаваемый силуэт без полной опоры на цвет (тест: grayscale-режим — все классы линий и силуэты узлов остаются различимы по форме/паттерну на ≥4/5).
3. Цвет кабеля и цвет в легенде совпадают на всех экранах (`/networks/[id]`, sandbox, global map).
4. Цвета линий и узлов соответствуют `CABLE_COLORS` и `NODE_VISUALS`. Никаких локальных hex для кабелей в рендерах.
5. Кластер из 20 маркеров не превращается в единое цветное пятно: тёмный halo сохраняет границы каждой иконки.
6. Тултипы читаются на светлых тайлах (контраст текст/фон ≥ 4.5:1).

## 7. Manual QA — 10-минутный smoke

- Open `/global-network` или MapView, zoom 4 → 8 → 13. Проверить:
  - все классы кабелей различимы (цвет + dash);
  - подземные/satellite имеют правильный пунктир;
  - underground выглядит штрихом, satellite короткими тире.
- Open `/networks/<id>` 2D, переключить вид. Сравнить визуально с MapView для тех же координат — паритет.
- Open `/sandbox`, добавить по одному узлу каждого типа. Проверить:
  - силуэты разные;
  - тёмный halo читается на светлых OSM-фрагментах;
  - bloom отсутствует.
- Hover/Tap по узлу/кабелю — тултип читаем.
- Сравнить легенду (`ProposalLegend`/`GlobeLegendBody`) с реальным рендером — 1:1.

## 8. Что менять, если палитра расширяется

1. Добавить токен в `CABLE_COLORS` или `NODE_VISUALS`.
2. Обновить легенды: `ProposalLegend` и `GlobeLegendBody`.
3. Обновить sandbox `ELEMENT_TYPES` (если новый тип нужно строить руками).
4. Прогнать QA из секции 7.
